# ВосьмиБитва

Русскоязычный сайт турнира NES/Famicom от FoxyShadow: турнирная сетка, призовые места, участники, список игр, выигранные игроками игры в каждой встрече, правила и ссылки на трансляции. Готовый статический сайт для GitHub Pages на HTML, CSS и JavaScript с локальными шрифтами и изображениями. Сборка, база данных, API-ключи и установка зависимостей не нужны. Node.js используется только для локального сервера и тестов.

## Публикация

1. Сохраните изменения в репозитории `fox-8-bit`, создайте коммит и отправьте его в GitHub. Файл `index.html` должен находиться в корне публикуемого репозитория.
2. В репозитории откройте **Settings → Pages → Build and deployment**.
3. Выберите **Deploy from a branch**, ветку **master**, каталог **/ (root)** и сохраните настройки. Если используете другую ветку, выберите её.
4. Дождитесь успешной публикации. Последующие коммиты в выбранную ветку будут публиковаться автоматически.

Файл `.nojekyll` отключает обработку Jekyll. В `CNAME` указан домен `8battle.decavoid.com`; пользовательский домен и HTTPS настраиваются в GitHub Pages, а DNS — у DNS-провайдера. Пути к ресурсам и данным относительные, поэтому сайт поддерживает размещение как в корне домена, так и в подпапке `/fox-8-bit/`.

Основание для настройки: [документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Обновление турнира

Редактируйте файлы в `data/`, сохраняйте в UTF-8 и отправляйте изменения в GitHub. Видимая вкладка проверяет обновления `data/scores.txt` и `data/nes-games-won-by-player.txt` раз в минуту; при возвращении на вкладку оба файла запрашиваются сразу. Файлы `data/players.txt`, `data/games.txt` и `data/rules.md` загружаются один раз при открытии страницы; чтобы увидеть их изменения, перезагрузите страницу. Результаты перерисовываются только при изменении данных. Поисковые запросы, выбранный этап, фильтр статуса матчей, раскрытый список игр и открытые правила сохраняются при обновлении результатов, но не после перезагрузки страницы. Открытое окно результата обновляет счёт и списки обоих игроков при изменении данных, сохраняя фокус. Удаление списка игр не закрывает окно. Оно закрывается, если встреча удалена; для строки без корректного уникального `MatchId` — также если на её месте оказалась другая пара игроков.

| Файл | Содержимое |
| --- | --- |
| `data/scores.txt` | Этапы и пороги победы, матчи, счёт и официальные призовые места |
| `data/nes-games-won-by-player.txt` | Игры, выигранные каждым игроком в конкретном матче |
| `data/players.txt` | Один ник участника на строку |
| `data/games.txt` | Одно название игры NES/Famicom на строку |
| `data/rules.md` | Полный текст правил в Markdown, даты и призы |

При первой загрузке недоступного файла соответствующий раздел показывает ошибку с кнопкой «Повторить загрузку». Кнопка повторяет загрузку результатов, выигранных игр и файлов, которые ещё не удалось загрузить. Если файл выигранных игр недоступен, сетка и счёт продолжают отображаться, а уведомление позволяет повторить загрузку. При сбое очередного обновления остаются последние успешно загруженные результаты и списки выигранных игр.

### Участники

В `data/players.txt` укажите по одному нику на строку. Пробелы по краям, пустые строки и точные повторы удаляются; порядок остальных строк сохраняется. Этот список задаёт число участников в верхнем блоке сайта независимо от состава матчей. Нажатие на участника сбрасывает фильтры этапа и статуса, подставляет его ник в поиск матчей и переводит к сетке.

### Игры NES/Famicom

Раздел «Список игр» показывает названия из `data/games.txt` в порядке строк файла, с поиском по названию без учёта регистра. Количество игр и результаты поиска объявляются программами экранного доступа без видимого счётчика. Пробелы по краям, пустые строки и точные повторы удаляются. Названия с апострофами, амперсандами и другой пунктуацией сохраняются как текст.

Сначала показаны 12 игр, а на экранах шириной до 660 px включительно — 6. Кнопка «Показать все …» раскрывает полный список, «Свернуть» возвращает компактный вид. Поиск всегда работает по всем играм и показывает все совпадения с исходными номерами; при очистке запроса восстанавливается выбранный раскрытый или компактный вид.

Ссылка «Список текстом» открывает исходный файл. Список служит справочником для турнирной рулетки; сама рулетка на сайте не реализована.

### Матчи

Этап — колонка турнирной сетки с матчами. Матч состоит из одного или нескольких раундов между двумя игроками. Раунд — одна партия в одной игре NES/Famicom; победа в раунде добавляет одно очко к счёту игрока в матче. Счёт показывает число выигранных раундов, а счётчик в заголовке этапа — число матчей.

Заголовки в квадратных скобках задают название этапа и порог победы: `[Этап 1 | win=2]`, `[Полуфиналы | win=3]`, `[Финал | win=5]`. `win` — обязательное положительное целое число, общее для всех матчей этапа, включая встречи внутри групп. На сайте отображается только название, без `| win=…`. Порог задаётся отдельно в каждом этапе и не наследуется из предыдущего. Изменение `win` пересчитывает победителей, фильтры и открытое окно результата при очередном обновлении данных.

Заголовок занимает всю строку; пробелы по краям названия и вокруг `|` и `=` не учитываются. Название — непустой текст без квадратных скобок и `|`; Markdown в нём не обрабатывается. Если `win` отсутствует, равен нулю или некорректен, сайт показывает предупреждение и сохраняет матчи со счётом, но не назначает победителей этого этапа. Старые заголовки без `win` и строки без заголовка читаются с таким же предупреждением; добавьте порог, чтобы завершённые матчи снова определялись.

Строка матча имеет пять полей: `MatchId | Игрок 1 | Счёт | Игрок 2 | Счёт`. `MatchId` — уникальный во всём турнире идентификатор встречи, например `A1`, `B1` или `C1`; по нему подключается список выигранных игр. Каждая из трёх встреч группы получает собственный идентификатор. Заголовок таблицы `MatchId | Player 1 | Score | Player 2 | Score` можно оставить. Допускаются внешние символы `|` и строки-разделители таблиц Markdown. Пустые строки важны.

Все строки, начинающиеся с `#` (после удаления пробелов по краям), считаются комментариями независимо от количества символов `#`. Пробел после `#` необязателен. Комментарии не разделяют группы матчей и допускаются также в разделе победителей. Чтобы закомментировать заголовок этапа, добавьте `#`: `# [Финал | win=5]`.

Идентификатор начинается с латинской буквы или цифры и может содержать латинские буквы, цифры, точки, дефисы и подчёркивания. Если идентификатор некорректен или повторяется, сайт показывает предупреждение и сохраняет матч со счётом, но не подключает к нему выигранные игры. Для повторяющегося идентификатора списки отключаются у всех его встреч.

Прежний формат из четырёх полей `Игрок 1 | Счёт | Игрок 2 | Счёт` также поддерживается, но к таким матчам нельзя привязать выигранные игры. Для подключения списков добавьте идентификаторы и в заголовок таблицы, и в строки матчей.

```text
[Этап 1 | win=2]
MatchId | Player 1 | Score | Player 2 | Score

A1 | Deeper | 1 | neradimo | 2

A2 | Serxio |   | Billy |

A3 | dilat    | 2 | Mr(A)ked    | 0
A4 | dilat    | 1 | arcade_user | 0
A5 | Mr(A)ked | 0 | arcade_user | 2
```

- Отдельные матчи разделяются пустой строкой.
- Три соседние строки без пустых строк образуют группу, если в них ровно три разных участника и каждая пара встречается один раз. Такая группа всегда отображается целиком, в том числе при поиске и фильтрации: три встречи в общей рамке, разделённые тонкими линиями. В каждой встрече игроки расположены друг под другом, отдельные ячейки счёта — справа, а ник и счёт победителя подсвечены. Когда завершены все три встречи и у одного игрока единственная наибольшая сумма очков за оба матча, золотистым цветом выделяются только его ник и счёт в обеих встречах; остальные два игрока не подсвечиваются. При незавершённой группе или равенстве наибольших сумм сохраняется подсветка победителей отдельных матчей. Окно результата всегда показывает победителя выбранного матча.
- Счёт записывается целым неотрицательным числом. Пустое поле, `—`, `–`, `-` или `?` означает, что результат ещё не указан. Ноль — настоящий счёт, а не отсутствие данных. Некорректное значение вызывает предупреждение и считается отсутствующим результатом.
- Матч завершён, когда оба счёта указаны и ровно один игрок набрал не меньше `win`, а второй набрал меньше `win`. Ник и счёт победителя подсвечиваются золотистым цветом. Например, при `win=2` счёт `1–0` ещё не определяет победителя, а `2–1` уже определяет; при `win=3` счёт `2–1` остаётся незавершённым. Можно записывать промежуточный счёт по ходу матча.
- Если оба игрока набрали не меньше `win`, сайт показывает предупреждение и не назначает победителя, даже если один счёт больше другого. Исправьте счёт или порог этапа.
- При равном, отсутствующем или ещё не достигшем порога счёте победитель не назначается. Все матчи без определённого победителя входят в фильтр «Незавершённые», включая записи с некорректным порогом или счётом.
- Два победителя группы определяются после завершения всех трёх встреч. Выбывает игрок, проигравший оба матча. Если у всех по одной победе в матчах, сравнивается суммарное число выигранных раундов в обеих встречах каждого игрока: выбывает участник с единственным наименьшим результатом. Например, при суммах A — 2, B — 3, C — 3 проходят B и C. Разница выигранных и проигранных раундов не используется. Если суммы равны у всех троих, сайт сообщает о переигровке группы; после неё замените три строки группы новыми результатами.
- Если у каждого по одной победе в матчах, а двое делят последнее место по выигранным раундам (например, 3, 2, 2), действующие правила не определяют выбывающего. Сайт сообщает, что требуется решение организатора, и не назначает двух победителей или переигровку автоматически.
- Пустые этапы показываются с сообщением, что соперники ещё не определены.
- Ошибки формата отображаются над сеткой. Соседние строки, не составляющие корректную тройку, показываются отдельными матчами с предупреждением.

Призовые места задаются явно, отдельно от результатов матчей; для раздела `[Победители]` параметр `win` не нужен:

```text
[Победители]
Place | Player

1 | dilat
2 | neradimo
3 | Serxio
```

До объявления победителей оставьте имена пустыми. Сайт не назначает чемпиона автоматически и не создаёт пары следующих этапов: их нужно вписать в `data/scores.txt`.

Примеры незавершённого и завершённого турнира находятся в `tests/fixtures/scores-upcoming.txt` и `tests/fixtures/scores-complete.txt`. Файл `data/scores.example.txt`, если он создан локально, исключён через `.gitignore`, не входит в репозиторий и не используется сайтом.

### Выигранные игры в матче

В `data/nes-games-won-by-player.txt` создайте отдельный блок для каждого игрока и встречи. Первая строка блока — `MatchId | Игрок` без внешних символов `|`, следующие строки — названия выигранных им игр NES/Famicom, по одному на строку. Разделяйте блоки пустой строкой. Строки, начинающиеся с `#`, считаются комментариями.

```text
# MatchId и ник должны совпадать с записью в scores.txt
A1 | Deeper
The Addams Family

A1 | neradimo
Adventures in Magic Kingdom
Balloon Fight

A2 | Billy
```

Идентификатор и ник должны точно совпадать с `data/scores.txt`, включая регистр букв; пробелы по краям полей удаляются. При переименовании игрока или изменении идентификатора обновите оба файла. Для встреч группы используются их отдельные `MatchId`, а не общий идентификатор группы. Названия и их порядок сохраняются; повторяющееся название тоже остаётся в списке, если игрок выиграл одну игру несколько раз. Несколько блоков с одной парой `MatchId | Игрок` объединяются.

Вся панель встречи из двух игроков — стандартная кнопка: её можно нажать мышью или открыть клавишей Enter либо пробелом. В группе каждая из трёх встреч открывается отдельно. Ячейки счёта показываются без подчёркивания. Окно доступно у всех матчей, даже если списки выигранных игр ещё не заполнены. Размер карточки остаётся прежним, в том числе при открытом окне.

Модальное окно браузера (`dialog`) имеет пиксельный заголовок «Результат матча»: ники соперников расположены по краям, ячейки счёта — по центру, списки выигранных игр — в двух колонках под ними. Победитель показан слева, его ник и счёт выделены золотистым цветом; проигравший расположен справа и выделен серым. Пока победитель не определён по порогу этапа, сохраняется порядок игроков из файла без подсветки победителя и проигравшего. Повторяющей результат текстовой подписи в окне нет. На узком экране ники остаются в первой строке, счёт располагается по центру следующей, а списки сохраняют две колонки.

Закрыть окно можно кнопкой «×», клавишей Escape или нажатием на затемнённую область вокруг него. Фокус возвращается к панели встречи, в том числе после обновления сетки; если она больше недоступна — к поиску матчей.

Пустой блок игрока означает, что в нём не перечислены выигранные игры; отсутствие блока означает, что сведения для игрока не указаны. Если названий нет, окно показывает «Нет выигранных раундов.» при нулевом счёте и «Игры пока не указаны.» в остальных случаях. Сайт не дополняет списки названиями на основании счёта.

Счёт и победители всегда определяются по `data/scores.txt`, а не по числу названий игр. Списки служат подробностями матча и могут заполняться отдельно от результатов. Публикуйте изменения обоих файлов вместе, чтобы названия и счёт соответствовали друг другу.

### Правила, даты и призы

Каждый раздел `##` в `data/rules.md` становится раскрывающимся блоком; при первой загрузке первый раздел открыт. Номера разделов и подразделов убираются из отображаемых заголовков, сохраняясь в исходном файле. Поддерживаются заголовки, абзацы, жирный и курсивный текст, списки, цитаты, встроенный код, ссылки и переносы строк через два пробела. HTML выводится текстом; таблицы и изображения Markdown не поддерживаются.

Дата и призовые суммы на главной странице извлекаются из текста правил. Чтобы сайт распознавал их, сохраните текущую форму предложений, например:

```text
Турнир будет проходить 6, 7 и 8 ноября (если участников будет немного, то 7 и 8 ноября).
Призовой фонд турнира составит 25000 рублей.
Первое место получает 18000 рублей, второе 6000 рублей, третье 1000 рублей.
```

Если дата или сумма не распознана, сайт покажет «Даты в правилах», «Призы турнира» или номер призового места вместо суммы. Ссылка с датой ведёт к правилам. Основной заголовок `#` из файла не дублируется; вводный текст и содержимое разделов отображаются на странице. Год и время начала не извлекаются из правил.

Ссылки на Twitch и YouTube находятся в `index.html`. Они ведут на каналы FoxyShadow и не предполагают, что трансляция уже идёт. Название «ВосьмиБитва» также редактируется в `index.html`. Крупная дата под названием обновляется из правил; ссылка ведёт к полному тексту с оговоркой о числе участников.

## Локальный просмотр

Для локальной работы рекомендуется Node.js 22 или новее с npm. Команды выполняются из каталога `fox-8-bit`, где находится `package.json`; `npm install` не требуется:

```sh
npm start
```

Откройте `http://127.0.0.1:4173/`. Для проверки размещения в подпапке доступен `http://127.0.0.1:4173/fox-8-bit/`. Остановка — `Ctrl+C`. Сервер слушает только локальный интерфейс; порт можно изменить переменной окружения `PORT`. Автоматически обновляются `data/scores.txt` и `data/nes-games-won-by-player.txt`; после изменения остальных файлов перезагрузите страницу. Простое открытие `index.html` через `file://` не подходит: браузер блокирует чтение файлов данных через `fetch`.

## Проверки

```sh
npm test
```

Команда запускает встроенный тестовый раннер Node.js (`node --test`). Тесты проверяют функции из `assets/tournament.js`: пороги `win` для каждого этапа, промежуточный счёт, отсутствующие и некорректные пороги, достижение порога обоими игроками, пересчёт победителей и фильтров при изменении порога, завершённые и будущие матчи, пустые и нулевые значения, группировку, приоритет побед в матчах, сравнение сумм выигранных раундов при одной победе у каждого, переигровку при равных суммах у всех троих, неразрешённую ничью за последнее место, поиск и фильтры матчей, призовые места, список участников, извлечение дат и призов, Markdown и защиту от HTML-вставок. Для выигранных игр проверяются пятиколоночный формат и прежний формат счёта, уникальность и корректность `MatchId`, точная привязка к игроку и матчу, пустые блоки, повторы названий и обработка ошибок формата. Стабильные примеры находятся в `tests/fixtures/`, поэтому изменение числа игроков и результатов турнира не требует переписывать тесты. Дополнительно проверяются формат текущих `data/scores.txt` и `data/nes-games-won-by-player.txt`, существование указанных матчей и участие в них указанных игроков.

Браузерные взаимодействия и вёрстка этими тестами не проверяются. После изменения интерфейса проверьте локально поиск и фильтры, раскрытие списка игр и правил, а также узкий и широкий экран. Для окна результата проверьте нажатие на всю панель отдельных и групповых встреч, открытие с клавиатуры, правильную перестановку победителя вместе со счётом и списком игр, равный и отсутствующий счёт, пустые списки, закрытие всеми тремя способами и возврат фокуса. Проверьте обновление открытого окна, сохранение окна при удалении списка, закрытие при удалении встречи и неизменность размеров карточек.

## Файлы сайта

- `index.html` — структура, основной текст, навигация и ссылки на трансляции.
- `assets/styles.css` — оформление и адаптивные раскладки.
- `assets/app.js` — загрузка и обновление данных, отображение, поиск и фильтры.
- `assets/tournament.js` — независимые функции чтения данных и подсчёта результатов.
- `assets/favicon.png` — иконка вкладки и логотип в шапке и подвале сайта.
- `assets/aniyuki-kitsune-flipped.gif` — анимированная лиса в блоке трансляций.
- `assets/fonts/` — Nihonium 113, Golos Text ExtraBold (для символа рубля) и Russo One; для Golos Text и Russo One включены лицензии SIL Open Font License.
- `data/` — редактируемые данные турнира.
- `scripts/serve.mjs` — локальный HTTP-сервер без внешних зависимостей.
- `tests/tournament.test.js` и `tests/fixtures/` — тесты обработки данных и примеры турнира.
- `package.json` — команды `npm start` и `npm test`.
- `CNAME` и `.nojekyll` — файлы для публикации на GitHub Pages.

Все шрифты и изображения загружаются с самого сайта. Пиксельный Nihonium 113 используется для основного текста, названия, даты, навигации, заголовков, ников, счёта и названий игр; запасной шрифт — локальный Russo One. Символ рубля в призовых суммах набран Golos Text ExtraBold. Загрузка шрифтов не блокирует отображение страницы (`font-display: swap`). Внешние скрипты и аналитика не используются.

При изменении оформления используйте для пиксельного шрифта только чётные размеры в пикселях. Для плавно меняющихся размеров в CSS применяется `round(..., 2px)` с чётным запасным значением.
